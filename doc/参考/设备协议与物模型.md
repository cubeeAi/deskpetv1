# 设备协议与物模型

## 当前模型及并存差异

[DeskBuddy 模型](../deskbuddy-v1-thing-model.json)对应当前显示型设备，[服务实现](../../main/services/app_services.cpp)决定实际可执行范围。仓库还保留[通用 DeskPet 模型](../deskpet-v1-thing-model.json)作为历史产品资料；其中 move、speak、volume、碰撞等不能用于当前 DeskBuddy 能力声明，也不能直接覆盖当前产品。

Core 当前使用 cubee 前缀，而本固件 build_mqtt_topics 固定 pet。它构造 mqtt://host:port，不是 TLS 客户端；改变端口为 8883 不会自动启用 TLS。跨仓适配未完成。

## Topic 与信封

ClientId/username 使用设备 ID，password 使用该设备 secret。参数优先取 factory_nvs，缺项可回退编译期默认；没有有效 secret 或仍为占位值时禁用 MQTT。

| 方向 | Topic | QoS |
| --- | --- | --- |
| 订阅 | `pet/{deviceId}/cmd`、`pet/{deviceId}/resp` | 1 |
| 发布 | `pet/{deviceId}/telemetry` | 0 |
| 发布 | `pet/{deviceId}/cmd/ack`、`pet/{deviceId}/event`、`pet/{deviceId}/req` | 1 |

命令需要 schemaVersion=1、非空 type/reqId。最近 12 个 reqId 在执行前记入内存，包括之后失败的命令；重复回 DUPLICATE，不重放原执行结果，重启后不保证去重。MQTT PUBACK 是传输结果，业务完成看 cmd/ack 及后续遥测。

```json
{"schemaVersion":1,"reqId":"deskbuddy-brightness-example","type":"setBrightness","ts":1790899200,"payload":{"brightness":50}}
```

## 服务、属性与错误

| 服务 type | payload 与行为 |
| --- | --- |
| setBrightness | brightness 数值经当前实现转整数后检查 0–100，设置 OLED 亮度并上报 |
| setEmotion | emotion 经 emotion_to_mood 映射；支持值见[枚举转换](../../main/app/app_types.cpp)，不是任意文本 |
| setPage | page 字符串经 parse_page 转页面，再上报 |
| setWeatherConfig | city/latitude/longitude/timezone；经纬度接收字符串或数值，更新后位置与时区非空，保存并刷新天气 |
| setWeatherTheme | theme 经预设主题解析，保存后更新显示 |
| reboot | 安排延迟重启并回 DONE；不是重启完成证明 |

`writeProperty`、`ota.switch` 和未列出的服务回 UNSUPPORTED_TYPE。模型把 brightness/weatherTheme 标为 RW，并不意味着本固件支持通用 writeProperty。物模型与当前执行器仍需对接方逐项匹配。

| ACK code | 当前含义 |
| --- | --- |
| DONE | 当前处理分支完成，或重启已安排 |
| BAD_PAYLOAD | JSON、字段、数值范围或枚举不合要求 |
| DUPLICATE | 当前缓存已见 reqId，ok=false |
| INTERNAL_ERROR | 保存用户配置失败 |
| UNSUPPORTED_TYPE | 没有该命令分支 |

遥测直接上报 rssi、brightness、version、wifiConnected、configPortalActive、currentPage/currentMood、城市/经纬度/时区、weatherTheme、当前天气、weatherReady 和 weatherForecast。周期全量、变化差量；字段类型及枚举结合模型 JSON 与实现核对：page_to_string 可将像素测试页上报为 pixelTest，touch 事件的 before/after 也可能包含该值，但模型未列入此枚举；parse_page 不接受 pixelTest，因此不能用 setPage 进入该页。不能补出未上报的硬件数据。本实现没有结构化 versionInfo 和 OTA 安装链，version 字符串不是 OTA 对账事实。

事件为 touch、configPortalEntered、wifiConnectFailed、weatherRefreshFailed，使用 eventId/eventType/timestamp/params。服务端租户与设备归属由凭据解析，设备不能自己声明权限。

排查无响应先看前缀/TLS差异，再看 reqId、支持分支与参数；天气按请求生命周期定位，不通过重复发送掩盖 pending 或错误。示例仅供获准的隔离验证；pet/cubee 前缀差异须先完成适配。

## 天气请求与响应

实现入口为 app_services.cpp 的 update_weather、handle_mqtt_response 和 parse_weather_response_payload。WiFi、MQTT 与位置配置就绪后，设备向 `pet/{deviceId}/req` 发请求；已有 pending 请求时不重复发起。经纬度在请求中为数值，city 为显示城市，timezone 为时区字符串：

```json
{
  "schemaVersion": 1,
  "reqId": "weather-1790899200000-1234abcd",
  "type": "getWeather",
  "ts": 1790899200,
  "payload": {
    "city": "Shenzhen",
    "latitude": 22.5431,
    "longitude": 114.0579,
    "timezone": "Asia/Shanghai"
  }
}
```

对应服务在 `pet/{deviceId}/resp` 返回同一 reqId。成功响应的完整字段示例如下；days 至少一项，固件最多读取前三项，多余项忽略：

```json
{
  "schemaVersion": 1,
  "reqId": "weather-1790899200000-1234abcd",
  "type": "getWeather",
  "ok": true,
  "code": "DONE",
  "message": "success",
  "ts": 1790899201,
  "payload": {
    "city": "Shenzhen",
    "timezone": "Asia/Shanghai",
    "weatherMain": "Rain",
    "weatherDesc": "小雨",
    "temperature": 29.5,
    "feelsLike": 33.2,
    "humidity": 78,
    "weatherForecast": {
      "days": [
        {
          "date": "2026-10-02",
          "weatherMain": "Rain",
          "weatherDesc": "小雨",
          "tempMin": 24.1,
          "tempMax": 29,
          "humidity": 81
        }
      ]
    }
  }
}
```

payload 中 city/timezone/weatherMain/weatherDesc 必须为字符串，temperature/feelsLike/humidity 必须为数值；每个被读取的预报项需要上述全部字段，date 使用 YYYY-MM-DD，星期标签由设备推导。温度及体感温度、预报最高/最低温度以摄氏度表示，湿度为百分比；固件按数值解析，湿度四舍五入为整数。city/timezone 虽会检查类型，但不会覆盖设备位置配置。成功分支要求 ok=true 且 code 为字符串，当前实现并未额外强制 code 等于 DONE。

失败响应无需 payload，例如：

```json
{
  "schemaVersion": 1,
  "reqId": "weather-1790899200000-1234abcd",
  "type": "getWeather",
  "ok": false,
  "code": "UPSTREAM_ERROR",
  "message": "weather service unavailable",
  "ts": 1790899201
}
```

响应只有在 schemaVersion=1、type=getWeather、reqId 非空且与当前 pending 请求完全匹配时才处理。非法 JSON、信封字段不符、不匹配或迟到响应被忽略；匹配响应缺少布尔 ok/字符串 code，或成功 payload 解析失败，会结束本次请求并报告 RESP PARSE。ok=false 对应 RESP FAIL；失败码映射为 BAD_PAYLOAD→400、UNSUPPORTED_TYPE→422、TIMEOUT→408、RATE_LIMITED→429、UPSTREAM_ERROR→502、INTERNAL_ERROR→500，未知码为 -60。

发布受理后按单调毫秒计时，15 秒未完成即 TIMEOUT；MQTT 断开会清除 pending。成功后更新天气、表情和遥测；失败保留已有天气并标记 stale，发布 weatherRefreshFailed 与遥测。message 和响应 ts 不参与固件的请求关联或超时判断。

## 时间字段与关联

| 字段 | 单位与解释 |
| --- | --- |
| 命令、req/resp、ACK、telemetry 的 ts | Unix 秒；本固件生成值取 std::time(nullptr)，未同步时不能据此宣称真实墙上时间准确，接收的命令/天气响应 ts 不用于匹配 |
| event 的 timestamp | 毫秒；current_timestamp_ms 在 epoch 达到 1700000000000 时用系统 epoch 毫秒，否则回退 esp_timer_get_time()/1000，即启动后的毫秒数，不是 Unix 时间 |
| 天气 reqId | 当前生成格式为 weather-毫秒值-随机后缀；当作不透明关联标识原样返回，不能从中推断可靠跨设备时钟 |
| 天气超时 | millis() 的单调毫秒差，与响应 ts 和事件 timestamp 无关 |

排查时同时记录设备启动/同步状态与 reqId；不能把同步前的 uptime 与服务端 Unix 时间直接相减。
