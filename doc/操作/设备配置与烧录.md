# 设备配置与烧录

## 配置分离

公共固件与每台设备的 factory_nvs 分开准备。用户 WiFi/位置/时区保存于默认 NVS 的 deskbuddy namespace；MQTT 出厂配置位于 factory_nvs/factory_cfg，网页不编辑 MQTT 身份。

[读取实现](../../main/services/app_services.cpp)读取 mqtt_host、mqtt_port、mqtt_device_id、mqtt_secret；生成器还写 product_key，但当前读取函数不使用它作设备身份或产品授权判断。不能把量产表格产品列当运行时权限依据。

[分区表](../../partitions_3m_app.csv)定义 nvs 0x9000/0x4000、factory_nvs 0xD000/0x2000 readonly、phy_init 0xF000/0x1000、factory 0x10000/0x300000。没有 OTA 双槽；readonly 标记不是凭据加密。

## 构建与配置门户

在 ESP-IDF 环境从仓库根构建，目标 ESP32-C3。仓库未提供完整受版本锁定的 SDK 环境，记录实际 IDF 版本及本地 sdkconfig；核对选择自定义 partitions_3m_app.csv，不能只凭文件存在推断构建用了它。

```bash
idf.py --version
idf.py build
```

首次目标设置可使用 `idf.py set-target esp32c3`，会重建配置，先保留需要的本地参数。构建与烧录仅在获准的隔离环境执行。

开机触摸保持约 3 秒或缺 WiFi 配置进入 DeskBuddy-Setup；配网入口通常为 192.168.4.1，热点参数以[板级常量](../../main/app/app_types.h)为准。网页保存 SSID、密码、显示位置、经纬度和时区，保存后安排重启。MQTT secret 必须经出厂分区准备，不应混进共享源码。

## 一机一码与交付

1. 按[NVS 工具](../../tools/factory_nvs/README.md)准备授权表格并核对设备 SN 唯一、产品筛选及目标 broker。
2. 审核生成数量与 CSV/BIN 配对，避免同 SN 覆盖或错配；这些文件含凭据，不能提交或随公共固件分发。
3. 按[打包工具](../../tools/flashing/README.md)从本次构建取公共镜像，并为每个设备装入正确 factory_nvs.bin。
4. 核对 build/flash_args 与批处理固定地址完全一致，在批准的测试板运行烧录；不能照搬不同板型/分区的地址。
5. 观察启动、NVS 来源、配网、设备身份和实际显示，再记录设备与镜像对应关系。

错误定位：读不到 factory_nvs 查分区选择/烧录地址/namespace；MQTT 禁用查 secret 是否缺失或占位；NVS 空间不足查生成 --size 与真实分区；天气未更新查经纬度和 pending 请求。固件日志只报告 secret 是否存在，报告中仍需脱敏设备和位置。

Windows BAT 实际写 flash，没有只读验证模式。生成身份包与调用 esptool 前须核对授权设备、镜像和凭据；文档校验不能代替硬件验收。
